# 每日报告

Eunomia 每日报告是一个独立的 AI 技术分析栏目。每篇报告从具体系统问题出发，比较一手证据，分析现有研究或生产实践仍然解释不了、测不出来或落不了地的部分，并提出可以继续做成研究系统或工程机制的方向。

**本栏目所有页面均由 AI 生成，未经过人工编辑审核。** 引用、事实、测量数字、解释和研究方向都可能存在错误。读者应回看一手来源，并在用于生产系统或重要决策前独立验证。

为了保持已有链接稳定，页面 URL 继续使用 `/research/`，但公开栏目名称改为“每日报告”。这些内容是面向读者的自动化分析草稿，不是同行评审论文，也不代表某位人类作者已经认可其中结论。

## 当前报告

### [多个 AI Agent 同时工作时，谁来保证最终结果是对的？](https://eunomia.dev/zh/research/parallel-agent-effect-serializability/)

`worktree`、沙箱和并行工具调用可以隔离 worker，却仍可能产生错误的组合结果。本文用代码修改、共享预算、审批和不可逆操作说明：并行 Agent 的结果在真正生效前，需要经过一次统一的验证和提交。文章还分析现有 benchmark 与工具效果契约的不足，并提出 Agent 事务层、语义冲突 benchmark 和自适应并发控制等方向。

### [AI Agent 轨迹到底该保留什么：固定证据预算下的可观测性设计](https://eunomia.dev/zh/research/agent-trace-evidence-budget/)

一次模型调用周围可能产生数百个系统事件，完整轨迹却仍可能缺少决定性的状态、权限和 provenance。本文提出 evidence portfolio，并进一步分析证据效用、可移植 schema、无偏自适应采集与同预算评测仍然存在的研究空白。

## 发布约定

一篇每日报告必须提供比流畅综述更多的价值：

- 问题会影响真实的系统或工程决策；
- 开头能让没有读过来源材料的技术读者直接理解；
- 使用相互独立的一手来源，并清楚区分测量事实与 AI 生成的解释；
- 指出真实分歧、缺失机制、生产失败或尚未解释的边界；
- 明确列出假设、适用范围、不确定性和可证伪条件；
- 必须有一节说明现有研究或生产实践还缺什么；
- 必须有一节提出少量 non-trivial 方向，每个方向说明机制、相对现有工作的新增点、可实现 artifact、评测方法、学术价值、生产价值和失败条件；
- 明确披露页面由 AI 生成，未经人工审核。

[博客](https://eunomia.dev/zh/blog/)继续保存项目文章、教程、release、工程解释和编辑文章。每日报告单独放置，避免把自动化分析包装成人类已经审核过的 Eunomia 研究成果。
