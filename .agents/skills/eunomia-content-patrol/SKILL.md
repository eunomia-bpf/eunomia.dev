# Eunomia Content Patrol

Run the content operation as a thin orchestrator. Delegate substantive work to
the owning skill, then confirm the public result without creating filler.

## Required Context

Read these before routing work:

- `CLAUDE.md`
- `.agents/README.md`
- `draft/plan/README.zh.md`
- `draft/plan/publishing-queue.zh.md`
- today's `draft/media/YYYY-MM-DD/` workspace and recent run log, when present
- `.github/publisher/media/README.md`
- `.github/publisher/media/community-feedback.md`
- `.github/publisher/media/not-published.md`
- relevant `.github/publisher/media/platforms/*.json`
- `.agents/skills/eunomia-research-report/SKILL.md` before routing a Daily Report

## Role Boundary

This skill:

- reads operational state;
- finds the first eligible authorized task;
- invokes the correct child skill;
- checks that content, PR, CI, deployment, and public URLs completed;
- updates the queue, ledger, and compact run record when useful.

It does not:

- search news or choose a thesis;
- write a Daily Report, Blog article, platform post, or reply;
- pretend a draft or open PR is a completed publication;
- remove disclosure from AI-generated content;
- publish AI-generated analysis into the Blog archive.

## Routing Map

- Invoke `eunomia-research-report` for source-grounded Daily Report research,
  thesis formation, gap analysis, idea design, bilingual writing, and report QA.
- Invoke `eunomia-social-radar` for public performance, citations, comments,
  discussions, and response opportunities.
- Invoke `blog-writer` and `blog-writing-style` for project articles, tutorials,
  releases, engineering explanations, and explicitly human-editorial Blog work.
- Invoke the matching platform publisher for authorized LinkedIn, Xiaohongshu,
  Zhihu, Juejin, X, Reddit, Medium, DEV, Hacker News, or Lobsters actions.
- Invoke `content-launch-planner` only when a new multi-platform launch needs a
  plan not already represented in the queue.

Do not duplicate a child skill's workflow inside this orchestrator.

## Daily Report Boundary

The public name is **Daily Report** / **每日报告**. Stable files and URLs remain:

- `docs/research/<slug>.md`
- `docs/research/<slug>.zh.md`
- `/research/<slug>/`
- `/zh/research/<slug>/`

AI-generated technical analysis belongs there, not under `docs/blog/posts/`.

Every Daily Report must:

- be labeled AI-generated and not human-reviewed near the top and bottom;
- avoid a human byline unless a human actually authored or reviewed it;
- contain a concrete research or production gap section;
- contain a small number of developed ideas with mechanism, delta, artifact,
  evaluation, academic value, production value, and failure condition;
- use `Daily Report` rather than `Research` as the public tag and section label;
- preserve existing `/research/` URLs when revising an article;
- pass the full site verification and deployment checks.

Do not convert an unreviewed Daily Report into a Blog article merely to make it
look authoritative. A later human-reviewed article may cite or replace a Daily
Report, but that requires explicit editorial work and must not silently inherit
an AI-generated byline or review status.

## Daily Orchestration

1. Read the rolling queue, prepared artifacts, platform ledgers, and the previous
   run's next action. A global pause or blocker overrides covered items.
2. Only the first eligible unfinished task explicitly marked `排队` is due.
   `待确认` and `阻塞` do not authorize publication; `跳过` records rejection.
3. Invoke `eunomia-social-radar` when the operation includes monitoring public
   content or conversations.
4. Invoke `eunomia-research-report` only when a Daily Report or broad analysis
   item is eligible and authorized. A scheduled run may return `no defensible
   thesis` without manufacturing a page.
5. When a Daily Report is produced, require bilingual pages, disclosure, gap and
   idea sections, primary-source verification, and duplicate-topic checks.
6. Use `seo-geo` only for metadata, canonical, hreflang, indexing, and link
   checks. SEO pressure must not create a report when the research gate failed.
7. Create a focused branch and PR. Inspect the complete diff, wait for required
   checks, merge only when green, and verify the exact merge commit deployed.
8. Verify the live English and Chinese pages, Daily Report navigation label,
   disclosure at both positions, stable URLs, and the rendered gap and idea
   sections.
9. Route any separately authorized platform adaptation to the matching publisher
   skill. The adaptation must preserve the AI-generated, not-human-reviewed
   disclosure.
10. Update the rolling queue and platform ledger first. Add a compact dated run
    record only when it helps future execution.

## Scheduled Execution Authority

The first eligible queue item explicitly marked `排队` is standing authorization
to complete the action described by that item end to end, including PR, merge,
deployment, or the named platform publication.

No other queue status grants that authority. Manual patrol runs do not inherit
standing authority unless the user explicitly asks to execute the tasks.

Never infer authorization for private messages, connection requests, follows,
likes, votes, account settings, monetization changes, or deletion.

## No-Filler Rule

A scheduler is allowed to finish with no public artifact. Do not create a Daily
Report when there is no defensible gap and no non-trivial idea. Do not publish a
source roundup, generic trend summary, or speculative list merely to satisfy
cadence.

A report task is complete only when the intended page is deployed and publicly
verified. A draft, prepared copy, run log, or green pre-merge check is not a
substitute.

## Run Summary

When a separate summary is useful, record one compact entry in
`draft/media/YYYY-MM-DD/run-log.md` containing:

- date and run mode;
- child skills invoked;
- Daily Report or platform URLs published;
- PR and merge commit;
- source window and selected thesis or `no defensible thesis`;
- deployment result;
- exact blockers and next action.

Do not copy full research reports, browsing transcripts, or raw metric
inventories into the run log.
